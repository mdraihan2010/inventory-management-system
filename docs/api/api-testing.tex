\section{Introduction}
This document covers the third step of the project, \textbf{Backend Development}. It has two parts:
\begin{enumerate}
  \item \textbf{Develop the backend:} the server that stands between the frontend and the database. It offers 55 API routes.
  \item \textbf{Test the APIs with Postman:} 92 test requests with 217 automatic checks. All of them passed.
\end{enumerate}
An \textbf{API} (Application Programming Interface) is a fixed way to ask the server for something. The frontend sends an HTTP request to a URL, the backend reads or changes the database, and it sends back a JSON answer. \textbf{Postman} is a tool that sends such requests directly, without the frontend, so the backend can be tested alone.

\subsection{How a request is handled}
Example: the frontend asks to complete a sale (\code{POST /api/v1/sales/:id/complete}).
\begin{enumerate}
  \item \textbf{Route.} Express finds the matching route in \code{salesRoutes.js}.
  \item \textbf{protect.} The middleware reads the token from the \code{Authorization} header and checks it. Without a valid token the answer is 401.
  \item \textbf{authorize.} The middleware checks the role of the user. If the role is not allowed the answer is 403.
  \item \textbf{Controller.} \code{saleController.js} validates the input. Wrong input gives 400.
  \item \textbf{Model and database.} The controller changes the data through the Mongoose models. Stock, stock history and the sale are changed inside one transaction. If there is not enough stock, everything is rolled back and the answer is 409.
  \item \textbf{Response.} The controller sends a JSON answer with a status code, and the action is written to the audit log.
\end{enumerate}

\subsection{Response format}
Every answer has the same shape, so the frontend can handle all APIs in one way.
\begin{lstlisting}[style=query]
// success
{ "success": true, "message": "Product created", "data": { ... } }

// error
{ "success": false, "message": "SKU already exists" }
\end{lstlisting}

\section{Authentication and Roles}
\subsection{Login with JWT}
\begin{enumerate}
  \item The user sends email and password to \code{POST /auth/login}.
  \item The server compares the password with the stored bcrypt hash.
  \item If it matches, the server signs a token that holds the user id and the role. The token is valid for one day.
  \item The frontend sends this token in the header of every later request:\\ \code{Authorization: Bearer <token>}
  \item On every request the server checks the token and also checks that the user still exists and is active. A deactivated user is blocked at once (test T92).
\end{enumerate}

\section{Testing with Postman}
\subsection{Test environment}
The tests create products, sales and users. To keep the real data safe, the backend is started with a separate command for testing:
\begin{lstlisting}[style=query]
cd server
pnpm dev:apitest
\end{lstlisting}
This runs the same backend code, but connected to the database \code{stockpilot\_api\_test} and on port 5050. Two test users (an Administrator and a Staff user) are created in that database. The real database is not touched.

\subsection{The Postman collection}
The collection file is \code{docs/api/StockPilot-API.postman\_collection.json}. It has 92 requests in 10 folders.
\begin{itemize}
  \item \textbf{Variables.} \code{baseUrl} holds the server address. The login requests save the tokens in variables, and every later request sends the token automatically.
  \item \textbf{Chained requests.} When a product, sale or purchase is created, its id is saved in a variable and used by the next requests. So the requests run in order, like a real working day.
  \item \textbf{Automatic checks.} Every request has a test script that checks the status code and the \code{success} field. Many requests also check values, for example the stock or the amount that is still due.
  \item \textbf{Negative tests.} 29 requests are expected to fail. They show that validation, role checks and business rules work.
\end{itemize}
The test script of request T22 (Create product):
\begin{lstlisting}[style=query]
pm.test("status is 201", () => pm.response.to.have.status(201));
let json = pm.response.json();
pm.test("success is true", () => pm.expect(json.success).to.eql(true));
pm.test("productId is saved", () => {
  pm.collectionVariables.set("productId", json.data._id);
});
pm.test("new product has zero stock", () =>
  pm.expect(json.data.currentStock).to.eql(0));
\end{lstlisting}

\subsection{How to run}
\begin{enumerate}
  \item Start the test server with \code{pnpm dev:apitest}.
  \item In Postman choose \emph{Import} and select the collection file.
  \item Open the collection, choose \emph{Run collection} and press \emph{Start run}.
  \item Postman runs all requests in order and shows every check as PASS or FAIL.
\end{enumerate}
